🐳 Dockerfile Keywords

📖 What is a Dockerfile?

A Dockerfile is a recipe that tells Docker how to build your application image. Each keyword is an instruction that adds a layer to the image.

📋 Complete List of Dockerfile Keywords

1️⃣ FROM
🎯 Sets the base image
FROM ubuntu:22.04
FROM alpine:latest
FROM node:18-alpine
FROM python:3.11-slim
FROM golang:1.21-alpine
💡 Every container starts from an existing image. This is always the first instruction.
2️⃣ WORKDIR
🎯 Sets working directory (like `cd`)
WORKDIR /app
WORKDIR /usr/src/app
WORKDIR /home/node/app
💡 All following commands (RUN, CMD, COPY) will run from this directory.
3️⃣ COPY
🎯 Copies files from host to container
COPY . /app
COPY package.json .
COPY go.mod go.sum ./
COPY --chown=node:node . /app
💡 Your application code needs to be inside the container to run.
4️⃣ ADD
🎯 Advanced COPY + archive extraction + remote URLs
ADD . /app
ADD archive.tar.gz /app/
ADD https://example.com/file /tmp/
💡 Use COPY unless you need automatic tar extraction or URL downloads.
5️⃣ RUN
🎯 Executes commands during build
RUN apt-get update && apt-get install -y python3
RUN npm install
RUN go mod download
RUN mkdir -p /app/logs
💡 Prepares your environment (install dependencies, create folders).
6️⃣ CMD
🎯 Default command when container starts (can be overridden)
CMD ["node", "app.js"]
CMD ["./main"]
CMD ["npm", "start"]
💡 Only one CMD per Dockerfile. Last one wins. Can be overridden by `docker run` arguments.
7️⃣ ENTRYPOINT
🎯 Main command (cannot be overridden easily)
ENTRYPOINT ["node"]
CMD ["app.js"]

ENTRYPOINT ["./main"]
CMD ["--help"]
💡 CMD can be overridden, ENTRYPOINT always runs. Together they work great.
8️⃣ EXPOSE
🎯 Documents which port the container listens on
EXPOSE 8080
EXPOSE 3000
EXPOSE 80
EXPOSE 5432
💡 This is documentation only! Use `-p` with `docker run` to actually publish the port.
9️⃣ ENV
🎯 Sets environment variables inside container
ENV NODE_ENV=production
ENV PORT=8080
ENV DB_HOST=localhost
ENV PATH="/myapp/bin:${PATH}"
💡 Configure your application without changing code.
🔟 ARG
🎯 Build-time variables (only available during build)
ARG VERSION=latest
ARG NODE_VERSION=18
RUN echo "Building version ${VERSION}"
💡 ARG disappears after build, ENV stays in container. Use `--build-arg` to set values.
1️⃣1️⃣ VOLUME
🎯 Creates a mount point for persistent data
VOLUME /data
VOLUME /var/lib/postgresql/data
VOLUME ["/app/logs", "/app/uploads"]
💡 Data in volumes survives container deletion and restarts.
1️⃣2️⃣ USER
🎯 Changes user for subsequent commands
RUN useradd -m appuser
USER appuser
USER node
USER 1000
💡 Running as root is a security risk. Always switch to a non-root user.
1️⃣3️⃣ LABEL
🎯 Adds metadata to image
LABEL version="1.0.0"
LABEL maintainer="john@example.com"
LABEL description="My awesome app"
💡 Helps organize and filter images with `docker image ls --filter`.
1️⃣4️⃣ HEALTHCHECK
🎯 Tests if container is working properly
HEALTHCHECK --interval=30s --timeout=3s \
  --retries=3 CMD curl -f http://localhost:8080/health || exit 1
💡 Docker can automatically restart unhealthy containers.
1️⃣5️⃣ SHELL
🎯 Changes default shell used for shell form commands
SHELL ["/bin/bash", "-c"]
SHELL ["/bin/sh", "-c"]
SHELL ["powershell", "-Command"]
💡 Useful for Windows containers or when you need bash features.
1️⃣6️⃣ STOPSIGNAL
🎯 Sets the system call signal to stop the container
STOPSIGNAL SIGTERM
STOPSIGNAL SIGINT
STOPSIGNAL SIGKILL
💡 Some apps need a specific signal for graceful shutdown.
1️⃣7️⃣ ONBUILD
🎯 Triggers when image is used as a base for another build
ONBUILD COPY . /app
ONBUILD RUN npm install

# In child Dockerfile:
FROM parent-image  # ONBUILD commands run here
💡 Useful for creating base images that need to copy app code later.

⚖️ CMD vs ENTRYPOINT - Key Differences

Feature CMD ENTRYPOINT
Can be overridden ✅ Yes (by `docker run` arguments) ❌ No (use `--entrypoint` to override)
Default behavior Provides defaults for executable Defines the main executable
Best for Providing default arguments Setting the main process
Together they work as ENTRYPOINT defines executable, CMD provides default arguments

🎯 Practical Example - Complete Dockerfile

Dockerfile for Go Application
# 1. Start from Go base image
FROM golang:1.21-alpine

# 2. Set working directory
WORKDIR /app

# 3. Copy dependency files (better caching)
COPY go.mod go.sum ./

# 4. Download dependencies
RUN go mod download

# 5. Copy all source code
COPY . .

# 6. Build the application
RUN go build -o main .

# 7. Document the port
EXPOSE 8080

# 8. Run the application
CMD ["./main"]

💡 Best Practices Summary

✅ Order matters - Put frequently changing files at the end for better caching
✅ Combine RUN commands - Use `&&` to reduce layers: `RUN apt update && apt install -y curl`
✅ Use specific tags - `FROM node:18-alpine` not `FROM node:latest`
✅ Clean up in same layer - Remove temp files in same RUN command
✅ Prefer COPY over ADD - Unless you need extraction or URLs
✅ Use .dockerignore - Exclude unnecessary files (like .git, node_modules)
✅ Switch to non-root user - Use `USER` instruction for security

📊 Quick Reference Table

Keyword Purpose When to Use
FROM Base image First line of every Dockerfile
WORKDIR Set working directory Before copying code
COPY Copy files To add application code
RUN Run commands To install dependencies
CMD Default command To define how container runs
EXPOSE Document port To show which port app uses
ENV Environment variables For configuration
ARG Build-time vars For version, build flags
VOLUME Persistent storage For database, uploads
USER Switch user For security (avoid root)
HEALTHCHECK Monitor app For production containers
ENTRYPOINT Main process For CLI tools, scripts
